GLADIUS × vLLM 持续 Serving 接口规范

Canonical contract 1.0.0 · 2026-07-31 · 执行端规范来源：gladius_vllm

本文冻结控制面与执行面的文件协议。vLLM fork 不兼容旧的整数 schema_version、扁平 admission_limit、 GLADIUS_POLICY_PATH 或 GLADIUS_TELEMETRY_PATH。 SMIG 必须一次性切换。

1. Canonical policy snapshot

{
  "schema_version": "1.0.0",
  "generation": 42,
  "policy_id": "policy-42",
  "model_id": "Qwen/Qwen3-8B",
  "engine_id": "engine-a",
  "created_at": "2026-07-31T00:00:00Z",
  "expires_at": "2026-07-31T00:05:00Z",
  "admission": {
    "max_num_seqs": 8,
    "max_num_batched_tokens": 2048
  }
}
  • 顶层字段严格匹配；未知或缺失字段均视为 corrupt。
  • publisher 仅写 1.0.0；reader 接受语义版本格式且 major 为 1。
  • generation 是非负整数，并按 (engine_id, model_id) 持久化、严格递增。
  • ID 均为非空字符串；snapshot 的 engine/model 必须与执行实例精确匹配。生产必须显式配置稳定的 GLADIUS_ENGINE_ID。
  • 时间戳必须带时区，且 expires_at > created_at。
  • 两项 admission 只能是正整数或 null；null 表示使用启动 ceiling。
  • 发布必须同目录写临时文件、flush/fsync 后原子 replace；执行端不观察半行或半对象。

2. Telemetry schema

每个采样 scheduler step 追加一行 JSON。核心关联字段为 engine_id/model_id/generation/policy_id/decision_id/window_id/step。 decision_id 在 1.0 中等于 policy_id； 执行端无法由 canonical snapshot 得知 window_id 时写 null， 由 SMIG 发布账本完成 window→decision 映射。

{
  "schema_version": "1.0.0",
  "engine_id": "engine-a",
  "model_id": "Qwen/Qwen3-8B",
  "generation": 42,
  "policy_id": "policy-42",
  "decision_id": "policy-42",
  "window_id": null,
  "step": 901,
  "created_at": "2026-07-31T00:01:00Z",
  "expires_at": null,
  "num_running_reqs": 8,
  "num_waiting_reqs": 17,
  "num_skipped_waiting_reqs": 9,
  "num_scheduled_reqs": 4,
  "num_scheduled_tokens": 512,
  "num_prefill_reqs": 1,
  "num_decode_reqs": 3,
  "kv_cache_usage": 0.73,
  "policy_status": "active",
  "policy_source": "file",
  "requested_admission": {"max_num_seqs": 8, "max_num_batched_tokens": 2048},
  "effective_admission": {"max_num_seqs": 8, "max_num_batched_tokens": 2048},
  "clamped": {"max_num_seqs": false, "max_num_batched_tokens": false},
  "policy_poll_ns": 1100,
  "policy_apply_ns": 900,
  "telemetry_write_ns": 17000
}

写入、stats 构造、序列化、flush、close 或轮转失败均 fail-open：不得中断 serving。 采样率必须为正整数。生产 polling interval 必须大于 0；0 仅允许测试注入。 轮转保留完整 JSONL 行，不拆分记录。

2.1 Policy application acknowledgement

执行端首次观察到新 generation，或同一 generation 从渐进收缩转为完全生效时， 原子更新 policy_application.json。状态仅允许 active、attriting 与 fallback；确认写入失败保持 serving fail-open，但对应实验窗口不得进入学习经验。

{
  "schema_version": "1.0.0",
  "engine_id": "engine-a",
  "model_id": "Qwen/Qwen3-8B",
  "generation": 42,
  "policy_id": "policy-42",
  "decision_id": "policy-42",
  "observed_at": "2026-07-31T00:00:30Z",
  "scheduler_step": 901,
  "state": "active",
  "requested_admission": {"max_num_seqs": 8, "max_num_batched_tokens": 2048},
  "effective_admission": {"max_num_seqs": 8, "max_num_batched_tokens": 2048},
  "clamped": {"max_num_seqs": false, "max_num_batched_tokens": false}
}

3. 状态机与行为矩阵

输入状态存在未过期 last-good无可用 last-good
missing回到 startup default
expired回到 startup default，状态 expired
corrupt保留 last-goodstartup default，状态 corrupt
engine/model mismatch保留 last-goodstartup default，状态 rejected_engine_mismatch
generation regression/equal保留 last-goodstartup default，状态 rejected_regression
valid newer generation接受并替换 active policy

effective ceiling 始终为 requested 与 startup ceiling 的最小值。 降低 max_num_seqs 不驱逐运行中请求：先禁止新准入，再随完成自然收敛。 每步均重新检查 TTL；corrupt 新文件不能使已过期策略复活。

4. 配置与职责边界

唯一目录配置为 GLADIUS_POLICY_DIR，其下固定 policy_snapshot.json、policy_application.json 与 telemetry.jsonl。 gladius_vllm.scheduler.GladiusScheduler 是唯一有状态 scheduler； 其他入口只能无状态转发。

5. Provenance DAG

WorkloadWindow
  → CandidateSet
  → PolicyDecision
  → PublishedSnapshot
  → PolicyApplication
  → SchedulerStep*
  → ServingOutcome
  → RetainedExperience

DAG 必须保存连续 workload 特征、共同候选批次、选择 propensity、 硬件/引擎版本、telemetry step 范围、样本量和 P50/P95/P99。 未知的离线策略字段保持 null，不得伪造为 false 或 0。

7. P0–P4 路线与完成定义

  1. P0：本文、公共 parser、共享 golden fixtures。
  2. P1：双 ceiling scheduler、never-raises telemetry、SMIG canonical adapter。
  3. P2：Provenance DAG、严格窗口归因与真实跨仓闭环。
  4. P3：约束 replay、IPS/DR、shadow、canary、rollback。
  5. P4：TRAIL 风格 residual-length predictor 与 HyGen 风格 profiler。

可微 world model 只离线生成候选；梯度不得直接控制生产 scheduler。 任何真实 SLO、GPU smoke 或跨仓契约未通过时，都不得宣称持续学习 serving 闭环完成。

8. 测试证据与未解决风险

冻结测试覆盖 valid、非对象 JSON、坏 SemVer、naive timestamp、未知 admission、 engine/model mismatch、generation regression、expired 与原子替换；scheduler 覆盖 startup 等价、双 clamp、渐进收缩、last-good/expired 回退和 telemetry fail-open。 真实 engine/GPU、轮转压力、跨模型硬件矩阵和长时 SLO 仍是发布门禁，不以纯 Python 单测替代。

9. 下一同步目标（P0 → P1）

下一次两仓同步的唯一目标是：以本页 canonical snapshot 为共享 contract， vLLM 暴露公共 parse_policy_snapshot() 并补齐 last-good/telemetry fail-safe；SMIG 同时切换 publisher 与 telemetry adapter。两仓共同使用同一组 golden fixtures，通过 valid、SemVer、ID mismatch、regression、expired 和原子替换 契约测试后，再进入 Provenance DAG。

同步交付物：vLLM 公共 parser 与唯一 scheduler 状态机、requested/effective telemetry； SMIG 的 (engine_id, model_id) generation high-watermark 和新旧 telemetry 双读。 本目标不包含 residual-length predictor、HyGen profiler 或可微 world model。
